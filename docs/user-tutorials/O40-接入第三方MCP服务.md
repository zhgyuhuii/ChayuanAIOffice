## 一句话说明

「MCP 管理」是察元AI Office 的**出站** MCP 客户端：你把第三方 MCP 服务（高德地图、自建工具服务等）注册进来，应用作为客户端连过去验证、浏览其工具、按个开关启用；已启用服务的工具会自动注入首页 AI 对话，助手在聊天里就能直接调用。

## 适用场景

- 想让首页 AI 对话用上外部 MCP 服务的能力（地图检索、专用数据源、自建脚本服务等）；
- 手里有一个 MCP 服务的 URL（HTTP/SSE）或一条本地启动命令（stdio），想先验证它可用再接入；
- 接入后发现某个服务不想让对话用了，想临时停用而不删除配置。

典型提问（chabot 语料视角）：

- 「察元AI Office 怎么添加第三方 MCP 服务？」
- 「MCP 服务怎么验证通不通？工具在哪看？」
- 「加了 MCP 服务后 AI 对话怎么用它的工具？」

## 前置条件

- 已安装察元AI Office（本篇入口在应用设置里）。
- 第三方服务的接入信息三选一：HTTP/SSE 服务的 URL（http/https，需要鉴权时备好请求头），或 stdio 服务的启动命令（如 `npx -y some-mcp-server`）。
- 注意方向：本篇是「应用 → 连出去调别人」；「别人 → 连进来操作 Office」是另一台服务（设置▸集成▸本地 MCP 服务，见 [O38](./O38-MCP-Server.md)）。

## 操作步骤

**1. 打开入口：设置 → 「MCP 管理」**

- 设置侧栏有独立分区「**MCP 管理**」。页首说明原文：「添加外部 MCP 服务，本应用作为客户端连接并调用其工具；已启用服务的工具会自动进入首页对话。」
- 还没添加过时显示「暂未添加 MCP 服务，点击右上角「添加 MCP 服务」开始。」。

**2. 点「添加 MCP 服务」，逐字段填表**

- 「**名称**」：自定义名字，用于在列表里展示和给工具命名（占位示例「例如：高德地图」）；留空保存时报「名称不能为空」；
- 「**连接方式**」三选一（单选按钮组）：
  - 「**HTTP**」/「**SSE**」：显示「**服务地址**」（占位 `https://example.com/mcp`；必须 http(s) 开头，否则报「服务地址必须是 http(s) URL」）和「**请求头（JSON，可选）**」（占位 `{"Authorization": "Bearer …"}`；需要鉴权时填，JSON 格式写错报「JSON 格式有误，请检查请求头/环境变量」）；
  - 「**本地进程 (stdio)**」：显示「**命令**」（占位 `npx`；提示原文「启动本地命令并通过标准输入输出通信，例如 npx -y some-mcp-server」；留空报「本地进程的命令不能为空」）、「**参数（每行一个，可选）**」（占位 `-y` 换行 `@some/mcp-server`）、「**环境变量（JSON，可选）**」（占位 `{"API_KEY": "…"}`）；
- 新增的服务默认处于**启用**状态（编辑已有服务时保留其原启用状态）。

**3. 点「在线验证」再保存**

- 「**在线验证**」按钮当场连接该服务并拉取工具清单：成功显示「**连接成功，共 N 个工具**」，下方逐个列出工具名与描述；失败显示「验证失败: <原因>」；
- 确认无误后点「**保存**」，表单收起、服务进入列表。

**4. 管理列表中的服务**

- 每个服务一行：名称 + 连接方式标签 + 「**N 个工具**」（验证过）或「**未验证**」；
- 行尾开关：「**启用**」/「**已停用**」——切换只改生效与否，不改配置；停用的服务其工具不会进入对话；
- 「**编辑**」回到表单改字段；「**删除**」先变红色「**确认删除**」再点才真删；
- 点行首箭头展开：应用现连该服务拉取实时工具列表逐个展示，另有「**重新验证**」按钮；该服务没有工具时显示「该服务没有可用工具」。

**5. 在首页对话里使用**

- 已启用服务的工具自动注入首页 AI 对话的助手，命名格式 `mcp__<服务名>__<工具名>`；
- 正常聊天提需求即可，助手自己决定调用哪个工具；你也可以直接点名（例如「用 mcp__高德地图__xx 工具查一下…」）。

### 验证

1. 「MCP 管理」列表该服务行显示「N 个工具」且开关为启用；展开能看到工具名清单；
2. 切到首页 AI 对话，提问一个会用该工具的问题（如接了地图服务就问「附近有什么咖啡馆」），回复中能看到 `mcp__<服务名>__<工具名>` 的工具调用；
3. 把开关切到「已停用」再问同类问题：对话不再调用该服务的工具（重新启用即恢复）。

## 常见问题

**Q1：「验证失败」怎么排？**
按类型查：HTTP/SSE 先确认 URL 能从浏览器/`curl` 直达（注意 `/mcp` 这类路径后缀、是否需要 Bearer 请求头）；stdio 先在终端手动跑一遍「命令 + 参数」确认能启动。密钥过期、代理拦截也会导致失败；改好后点「重新验证」。

**Q2：保存时报「JSON 格式有误」？**
「请求头」或「环境变量」框里填的不是合法 JSON 对象。格式应为 `{"键": "值"}` 的键值对；不需要时留空即可。

**Q3：接了很多服务，对话会变得很慢或很乱吗？**
应用对注入做了硬上限：最多 32 个服务、每个服务最多 200 个工具、注入对话的工具总量上限 400；连接超时 15 秒、单次工具调用超时 120 秒。服务太多时把不常用的停用即可，配置保留、随时再启用。

**Q4：删除服务会把对话记录里的工具调用删掉吗？**
不会。「删除」只移除这个服务的注册与连接；历史对话内容不受影响，只是之后无法再调用它的工具。

**Q5：MCP 管理和「本地 MCP 服务」有什么区别？**
方向相反：「MCP 管理」是应用**连出去**调用别人的 MCP 服务（本篇）；「本地 MCP 服务」在 设置▸集成，是应用**开放自己**给外部智能体操作 Office 文件（见 [O38](./O38-MCP-Server.md)）。两者配置互不相通。

**Q6：stdio 服务会被谁启动？什么时候退出？**
由察元AI Office 按注册的「命令 + 参数」在本机拉起并经标准输入输出通信；配置改动后旧连接作废、下次调用按新配置重连。第三方 npm 包请自行评估来源可信后再接入——它将以你的用户身份运行。
