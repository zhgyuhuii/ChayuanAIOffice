## 一句话说明

点侧栏底部的「反馈」气泡：联网时打开「察元AI在线客服」聊天窗，离线时弹出「关注我们」公众号二维码卡兜底。更新有两条链路：应用内自动/手动更新（stable/beta 通道，下载新版本安装包后重启安装）与官网静默检查（新版本系统通知、下载安装包到下载文件夹）。

## 适用场景

- 想报 bug、提需求、找人工客服；
- 想立刻检查有没有新版本，或改用 Beta 通道尝鲜；
- 断网/内网环境下想知道更新和反馈会怎么表现。

典型提问（chabot 语料视角）：

- 「怎么联系客服或提交反馈？」
- 「怎么手动检查更新？稳定版和 Beta 版有什么区别？」
- 「反馈/心跳会收集我的文档内容吗？」

## 前置条件

- 反馈与检查更新需要能访问官网 aidooo.com；全程离线时反馈走二维码卡、更新检查静默失败不报错。
- 应用内自动更新仅桌面安装版有效：Windows（NSIS 安装包）、macOS（zip，Squirrel 替换）、Linux 仅 AppImage 自更新；**deb 安装没有内置更新器**，用 `apt install ./新版本.deb` 手动升级。web/dsh 插件形态无应用内更新。

## 操作步骤

**第 1 步 · 发起反馈**

- 主页左下角账号行旁有一个气泡图标的「**反馈**」按钮，点击后应用先探测官网可达性（按钮短暂转圈）：
  - **联网**：弹出独立聊天窗「**察元AI在线客服**」（加载官网客服聊天页，与官网同一界面），直接与客服对话；窗内白名单外链交给系统浏览器打开；
  - **离线**：弹出「**关注我们**」二维码卡——「扫码关注公众号」，通过公众号联系。
- 产品内还保留了完整反馈表单（「反馈及建议」：类型「错误报告 / 功能需求 / 其他」+ 正文 + 「添加图片 / 添加附件 / 附上运行日志」+「发送」；提交经主进程送到 aidooo.com，与官网同一接口；离线时提示「当前离线：已存草稿，联网后打开反馈将自动重发」）。**当前版本表单入口未接线**，点反馈按钮直接走在线客服/二维码；表单为后续版本预留。

**第 2 步 · 手动检查更新**

- 菜单「**帮助 → 检查更新…**」：
  - 有新版本：打开「**软件更新**」卡片窗——「发现新版本」+「**立即更新**」/「**最小化**」；
  - 已是最新：弹「已是最新版本（{version}）。」；
  - 检查失败：弹「无法检查更新，请检查网络后重试。」；
  - 无自更新机制的运行形态（如 deb、开发运行）：弹「自动更新失败，请从下载页面获取最新版本并手动安装。」并可选「前往下载页面」。

**第 3 步 · 下载与安装**

- 点「立即更新」后显示「正在下载更新…」（带进度），完成后按钮变「**立即重启安装**」；点它关闭更新窗并重启安装新版本。
- 下载失败显示「更新下载失败，请检查网络后重试。」与「**重试**」；同一版本连续失败 2 次后转为「前往下载页面」手动下载（链接按你的通道/架构自动匹配安装包）。
- 点「最小化」本会话不再打扰；已下载完成的包会在你正常退出应用时自动安装（下次启动即新版本）。
- 应用内更新的节奏：启动 15 秒后首次静默检查，之后每 4 小时一次；发现新版本弹更新卡片窗。

**第 4 步 · 更新通道与自动检查开关（设置 → 关于）**

- 设置 → 「**关于**」分区：**版本**（当前版本号）；发现新版本时出现「**更新到 {版本}**」按钮（下载中变「正在下载更新（{百分比}%）」，完成变「**重启并安装**」）；「**更新通道**」——「稳定版」（默认）/「Beta 版」，切换后立即按新通道重新检查（从 beta 切回 stable 不会降级、已下载的另一通道安装包作废）；「**自动检查更新**」开关（默认开）——关闭后「启动时和后台都不再检查新版本；仍可在"帮助 › 检查更新"中手动检查。」

**第 5 步 · 官网静默更新链路（无需操作）**

- 应用另有一条官网同步链路：每 30 分钟一次匿名运行心跳、启动 30 秒后及每 4 小时检查官网新版本——发现新版本发**系统通知**，点击后把安装包下载到系统「下载」文件夹并在文件管理器中定位，手动安装。这条链路所有网络失败全部静默，断网零报错。

**第 6 步 · 数据收集边界**

- 官网心跳只带匿名设备标识（随机 UUID，无文档内容）。
- 匿名使用统计（Google Analytics 4）默认开、可随时在 设置 → 通用 关闭；Google 会接收公网 IP 与传输元数据，但**绝不收集文档内容或文件名**（详见 O06 第 15 项）。

### 验证

1. 点侧栏「反馈」：联网时应弹出「察元AI在线客服」聊天窗；断网后重试应弹出「关注我们」二维码卡。
2. 菜单「帮助 → 检查更新…」：正常联网时要么弹更新卡片窗，要么弹「已是最新版本（{version}）。」且括号内为当前版本号。
3. 设置 → 关于：版本号与「激活」菜单/关于对话框显示一致；更新通道切换后不再出现降级提示。
4. 关闭「自动检查更新」后重启应用：不再自动弹更新卡片，手动「检查更新…」仍可用。

## 常见问题

**Q1：更新卡片点了「最小化」还会再烦我吗？**
同一版本本次运行不再自动弹；已下载完的包会在退出时静默安装。想立刻续上，用「帮助 → 检查更新…」手动唤出（手动检查会无视「最小化」记录）。

**Q2：「重试」几次都失败怎么办？**
同一版本连续失败 2 次后，卡片自动转为手动方案：「前往下载页面」打开按你通道与架构匹配的安装包链接（兜底跳转 GitHub Releases 最新页）。下载后手动安装即可。

**Q3：deb 安装的 Linux 怎么升级？**
deb 包没有内置更新器。到下载页获取新 deb 后 `apt install ./<新版本>.deb` 升级；AppImage 用户可用应用内更新（就地替换 AppImage，无需 root）。

**Q4：反馈按钮点了没反应？**
按钮点击后先探测官网（短暂转圈）：探测期间再点无效；官网不通时会弹「关注我们」二维码卡。若既无聊天窗也无二维码，检查网络与代理后重试。

**Q5：Beta 版通道有什么风险？怎么切回来？**
Beta 通道跟踪 beta 更新源，版本比稳定版新但稳定性低。设置 → 关于 → 「更新通道」选回「稳定版」即可；切换不会把你降级到更旧的稳定版本，另一通道已下载的包自动作废。

## 形态差异

- **应用内更新卡片、检查更新菜单**仅桌面安装版（Windows NSIS / macOS / Linux AppImage）可用；deb 与开发运行转手动下载指引。
- **web 部署与 dsh 插件形态**没有应用内更新链路（升级由部署方更换服务端制品完成）。
- 反馈按钮属于主页壳，web/dsh 形态同样有主页与该按钮；但浏览器桥不提供官网探测能力（恒判离线），点击直接弹「关注我们」二维码卡——在线客服聊天窗仅桌面形态可达。
