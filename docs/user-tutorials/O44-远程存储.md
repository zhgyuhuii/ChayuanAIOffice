## 一句话说明

在设置里配置一个 S3 兼容对象存储（MinIO 等）或阿里云 OSS 作为「默认保存位置」：保存新文档时自动存入远端 bucket，本地文件不受影响；打开远端文档时自动落到本地缓存、保存时回写 bucket，断网自动进待同步队列、联网补传。

## 适用场景

- 团队用 MinIO / 阿里云 OSS 统一存文档，想在 Office 里「另存即上云」；
- 想确认误删能不能恢复（存储端版本控制检测）；
- 分不清远程存储、Markdown 图床、AI 附件三件事的边界。

典型提问（chabot 语料视角）：

- 「怎么把文档保存到 MinIO / OSS？」
- 「连接测试提示建议开启版本控制是什么意思？」
- 「断网时保存的文档去哪了？」

## 前置条件

- 有一个对象存储服务：S3 兼容端点（MinIO、各类 S3 网关等）或阿里云 OSS；准备好 Endpoint、Bucket、AccessKeyId、SecretAccessKey。
- 入口在主页壳的「设置」弹窗「远程存储」分区（桌面、web 部署与 dsh 插件形态均有主页与该分区；行为差异见「形态差异」）。

## 操作步骤

**第 1 步 · 打开设置 → 远程存储**

- 主页左下角账号行的齿轮按钮打开「设置」，左栏选「**远程存储**」。未配置时显示说明「保存新文档时自动存入默认远程位置；本地文件不受影响。」与「尚未配置远程存储。」。

**第 2 步 · 添加存储**

- 点「**添加存储**」，逐字段填写：
  - **名称**——配置的显示名；
  - **协议类型**——「S3 兼容（MinIO 等）」（默认）/「阿里云 OSS」；切换到 OSS 时 path-style 自动改为虚拟域名风格，切回 S3 恢复 path-style；
  - **Endpoint**——服务地址（占位示例 `http://127.0.0.1:9000`），必须以 http:// 或 https:// 开头；
  - **Region**——区域，默认 `us-east-1`；
  - **Bucket**——桶名；
  - **AccessKeyId / SecretAccessKey**——密钥（密码框）；
  - **路径前缀**——对象 key 前缀，默认 `chaoffice/`；
  - **path-style 寻址**——开关，默认开（MinIO 必须开启）；
  - **启用**——开关，默认开。
- 点「**测试连接**」（测试中显示「测试中…」）：
  - 成功显示「连接成功」，并追加版本控制检测结果三选一：「**已开启版本控制，误删可恢复。**」/「存储端未开启版本控制，建议开启以防误删。」/「无法检测版本控制状态，可到存储控制台确认。」；
  - 失败显示「连接失败」+ 具体错误。
- 点「**保存**」完成；必填项缺失时提示「请完整填写名称、Endpoint、Region、Bucket 和密钥。」。点「取消」放弃编辑。

**第 3 步 · 设为默认保存位置**

- 回到列表页，每个配置是一行单选：名称 · 「默认保存位置」标记（被选中时）· 「启用 ✕」（被停用时），下方小字显示 `Endpoint / Bucket / 路径前缀`。
- 选中某配置即设为默认远程位置；也可以保持选中「**本地（不使用远程存储）**」——默认状态，保存不进远端。
- 「**编辑**」回到表单修改；「**删除**」弹确认「删除配置不会删除远端文件，确定删除？」——只删本机配置，远端对象原样保留；删除默认配置后自动回落到「本地」。

**第 4 步 · 日常使用（自动，无需操作）**

- 默认位置指向远端时，**保存新文档**自动写入 bucket（应用内该文档以 `remote://配置ID/对象key` 标识）；
- 从最近/文件夹打开远端文档：先物化到本地缓存再打开，之后的保存自动回写 bucket；
- **断网**保存不丢（桌面形态）：改动落盘到本地待同步队列（每个文档一个槽位、只留最新内容，槽位文件即全部状态），应用启动时重建队列自动补传；上传冲突**绝不静默解决**——补传时发现远端已被别人改过，会把该槽位报告出来交由用户裁决；
- 重命名是**服务端改名**；删除远端文档没有回收站（确认弹窗是唯一防线）——这正是建议开启存储端版本控制的原因。

**第 5 步 · 分清三件相邻的事**

- **远程存储**（本篇）：整份文档的上云保存，配置在设置 → 远程存储；
- **Markdown 图床**（O33）：只管 Markdown 里粘贴/拖入的图片上传（图床设置在 Markdown 编辑器内，支持 S3/SM.MS/GitHub），与本文档的配置互不相干；
- **AI 对话附件**（O16）：把本机文件交给 AI 读，不涉及上传云存储。

### 验证

1. 「测试连接」返回「连接成功」+ 版本控制三态文案之一。
2. 设为默认位置后新建一个文档并保存，到对象存储控制台（或 `mc ls`/ossutil）查看 bucket：`路径前缀`（默认 `chaoffice/`）下应出现新对象。
3. 关掉网络再保存一次，恢复网络后重启应用，控制台上对象内容应为最新版本。

## 常见问题

**Q1：测试连接失败？**
按序检查：Endpoint 必须带 http:// 或 https://；MinIO 类服务必须保持「path-style 寻址」开启，阿里云 OSS 则应选「阿里云 OSS」协议（自动走虚拟域名）；AccessKeyId/SecretAccessKey 是否有效、bucket 是否存在、网络/代理是否放行该地址。

**Q2：删除配置会删掉远端文件吗？**
不会。弹窗原文「删除配置不会删除远端文件，确定删除？」——bucket 里的对象全部保留，只是本机不再指向它。

**Q3：断网时保存的文档会丢吗？**
不会。保存先落本地缓存与队列槽位（原子写），应用启动时自动补传；同一文档反复保存只留最新内容。若补传时发现远端内容已被他人修改（冲突），应用不会静默覆盖——该文档会被单独报告出来，由你决定怎么处理。

**Q4：提示「存储端未开启版本控制，建议开启以防误删。」还要处理吗？**
建议处理。对象存储没有回收站，删除即生效；到存储控制台为 bucket 开启版本控制后再点「测试连接」，应变为「已开启版本控制，误删可恢复。」

**Q5：以前保存的本地文件会被传上去吗？**
不会。远程存储只作用于「保存新文档时」走默认远程位置的文档；已有本地文件的位置与内容完全不受影响（设置页说明原文）。

## 形态差异

- 桌面安装包形态：远程文件桥由主进程承载（IPC），断网待同步队列持久化并在下次启动补传。
- **web 部署与 dsh 插件形态**：同样有主页与「设置 → 远程存储」（远程文件桥经 BFF 同源 `/rpc/remoteStorage/*`）；该形态的队列桥为空实现，断网补传行为不适用，配置与连接测试可用。
- dsh 插件形态同理（sidecar 与 web 部署共用同一套 BFF 构建，见 O47）。
