## 一句话说明

察元AI Office 打开和保存的是真实的 .docx/.xlsx/.pptx 文件，保存时只重新生成你真正编辑过的块，其余内容连同压缩包里的其他部件逐字节原样搬回——所以用 Word/WPS 再打开时，没编辑过的部分版式毫无变化（「打开保存无感」）。本篇讲清「什么时候会变、什么时候绝不变」，并给出几个你自己就能做的验证方法。

## 适用场景

- 公文/合同/标书对格式极敏感，担心「用别的编辑器打开再保存，版式就乱了」；
- 要把 .odt/.ods/.odp（LibreOffice/WPS 的 ODF 格式）导入进来，想知道哪些内容能转、哪些明确不转；
- 想把 HTML 页面变成 Word 文档，关心图片、图表变成什么样；
- 用 git 或文档比对系统管理文档，希望一次小修改不要在 diff 里变成整篇重写。

典型提问（chabot 语料视角）：

- 「用察元AI Office 保存 docx，Word 打开会不会变版式？」
- 「ODT/ODP 转换会不会猜？转不了的内容怎么处理？」
- 「为什么 1 个 GB 的大文档打开也不卡？图片存在哪？」

## 操作步骤

本篇是概念篇，没有要点的界面入口；下面每步是一个可操作的验证动作（在哪 → 做什么 → 看到什么）。

**1. 验证「无改动 = 原样」**

- 在 Docs 里打开一个由 Microsoft Word 或 WPS 生成的 .docx，不做任何编辑就关闭：应用不会写盘（文档未标记为已修改）；
- 引擎层面同样保证：一次保存如果最终所有块都与打开时相同且无页眉页脚/样式等附加变更，直接返回原文件字节，连 document.xml 都不重写。

**2. 验证「小改动 = 只有改动处变」**

- 打开上述 .docx，只修改一句话并保存；再用 Word/WPS 打开检查：字体、页眉页脚、图片、公式、编号等与保存前一致；
- 把保存后的文件用压缩工具打开（或把后缀临时改成 .zip 解压）：`word/media/` 里的图片与原文件逐字节一致，`styles.xml`、主题、嵌入字体等部件未被改动——引擎保存时「其余 zip 条目一律原样复制，不做解压再压缩」；
- 再解包对比 `word/document.xml`：未触碰段落的 XML 与原文件对应片段一致（引擎按块把原始 XML 逐字节拼回）；Markdown 笔记则更直观——一次小编辑后 git diff 只有那一行变化（Markdown 是纯文本，按块逐字写回）。

**3. 验证「ODF 导入：不近似、不猜测」**

- 打开一个 .odt：先弹确认框「转换 .odt 文档？」，逐项说明正文/标题/列表/表格/图片会转换过来，脚注、批注、文本框不会完整保留，并明示「原文件不会被修改，转换出的是独立副本」；点「转换并打开」后另存出 .docx 副本，原 .odt 修改时间不变；
- .odp → .pptx 同理；.ods/.ots 由表格的本机引擎转换副本，公式改写成 Excel 语法——无法证明改写正确的公式不硬转，保留该单元格的计算结果值（ODF 本就存着这个值）；
- 转换全部在本机完成；转换器遵循一条硬规则：无法证明可正确转换的构造型计入 `dropped`（丢弃清单），绝不近似成错误的标记；单个 zip 部件解压上限 64 MiB，超出按损坏文件拒绝（防解压炸弹）。

**4. 验证「HTML → Word」**

- 在 HTML 编辑器里「文件 ▸ 导出为 Word…」，用 Word/WPS 打开导出件：标题、段落、列表、表格是原生可编辑的 Word 内容；图表、图标、装饰盒这类没有 Word 对应物的视觉以截图保留外观；
- Markdown 编辑器同样可「导出为 Word…」「转换为 Docs 文档并打开」（见 [O33](./O33-Markdown编辑与双链图谱.md)）。

**5. 什么时候会变、什么时候绝不变（速查表）**

| 场景 | 会变的部分 | 绝不变的部分 |
|---|---|---|
| 保存编辑过的 .docx | 你编辑的块重新生成为 OOXML 片段（只引用文档已有样式；缺失的标题级别按 Word 内置定义补进 styles.xml） | 其余块按原文件逐字节拼回；其他 zip 部件原样复制；完全无改动时整文件原字节返回 |
| 大文档（图多/上 GB） | 无 | 图片按 sha256 锚定留在原文件里（渲染时按需供给），保存时把占位符换回原字节；zip 条目按存储字节搬运、不解压不重压，代价只是读 XML 部件 |
| Sheets（.xlsx） | 你编辑的单元格/图表按窄补丁写回 | 未触碰的工作表部件原样保留 |
| Slides（.pptx） | 你编辑的元素重新生成片段 | 没有脏元素时整个条目逐字节写回；其他条目原样复制 |
| ODF 导入 | 转出的是新副本（.docx/.xlsx/.pptx） | 原 .odt/.ods/.odp 文件只读不动；转不了的构造型进 dropped 清单而不是乱转 |
| HTML/Markdown 保存 | 你编辑处的连续片段 | 其余源码逐字保留；BOM/换行风格/末尾换行原样保留 |

**6. 背后的机制（一段话版）**

打开 docx 时：原文件先按内容哈希归档一份备份（归档件从此不被改动），引擎把 word/document.xml 解析成顶层块树，每个块带着自己在原文件里的字节位置与原始 XML 切片。保存时：被编辑的「脏块」重新生成 OOXML 片段拼接回原位，未触碰的块把原始 XML 逐字节拼回去，再把压缩包里其余条目按存储字节逐一复制进新包。Sheets/Slides 同一哲学：窄补丁、原样搬运。HTML 与 Markdown 编辑器同源：源码补丁/块级拼接 + BOM/CRLF/末尾换行保真。

### 验证

按上面「操作步骤」的 1～4 操作即可；最快的两条：①小改保存后用 Word/WPS 打开版式无感；②用压缩工具看保存后文件的 `word/media/` 图片与原图逐字节一致。

## 常见问题

**Q1：保存后的文件真的和 Word/WPS 完全兼容吗？**
打开和保存的都是标准 OOXML。设计目标就是「未触碰部分逐字节保留，Word/WPS 打开无感」；你编辑的块按 Word 规范重新生成，且只引用文档里已有的样式，不会引入让 Word 报修复的私有写法。

**Q2：为什么我只改了一个字，git diff 却还有别的变化？**
先确认对比的基线：若之前有别的软件保存过该文件，那些归一化不是察元AI Office 造成的。在察元AI Office 内做的一次编辑，未触碰块是逐字节写回的；换行风格、BOM、末尾换行也不改。若仍有意外差异，可以把文件发给我们排查（侧栏「反馈」）。

**Q3：ODT 里明明有脚注/批注，转过来怎么没了？**
ODF 转换按「能证明正确才转」执行：脚注、批注、文本框等构造型当前不完整保留，确认框里逐项写明，转换器内部把它们计入丢弃清单（dropped），不做近似猜测。对格式要求严格的文档，建议转换后核对确认框列出的这几类内容。

**Q4：HTML 导出 Word 后，为什么图表变成了一张图片？**
HTML 页面的视觉（图表、图标、装饰盒）没有等价的 Word 结构，导出时截图保留外观；文字、标题、列表、表格则转成原生 Word 内容可以继续编辑。想要纯文字版，可先在 HTML 编辑器里删掉装饰性视觉再导出。

**Q5：几百 MB 的 docx 打开很慢吗？图片会全部塞进内存吗？**
不会。浏览器可直接解码的图片（png/jpg/gif/bmp/webp/svg）留在磁盘上的原文件里，界面按需读取；保存时再把原字节换回。压缩包条目按存储字节搬运、不解压再压缩，大文档的代价主要是读取 XML 部件。

**Q6：PDF 呢？PDF 转换也保真吗？**
PDF 是「真文本编辑」（重写内容流、保留原字体，不是注释遮盖）与「全本地 PDF→Word/PPT/Excel 转换」，与本篇的 OOXML 往返是两条技术线，见 [O29](./O29-PDF真文本编辑与涂黑.md) 与 [O32](./O32-PDF转换导出.md)。
