## 现状病灶（共识基础）

1. 新建区 7 行全宽按钮固定占 ~190px，首屏一半给了低频操作，项目树被挤到视口下半。
2. 项目树/收藏/最近三段竖叠共用一个滚动区，互相挤压。
3. recents 的类型筛选 chips（all/docx/xlsx/pptx/pdf/.md）与树的功能语义重叠。
4. 文件行 checkbox+星标+hover 菜单视觉重；新方圆文件徽标缩到 15px 细节糊。
5. 云端 nav 孤立单行悬在中间。

## Q1 整体范式（已并入根问题裁定：Drive 式 + 侧栏单色化，待签细节见 Q2-Q11）

**建议：Drive 式**。顶部压成一行两钮：品牌色「＋ 新建」主钮（下拉菜单承载六种格式）+「打开」次钮；下方保留 项目树/收藏/最近 三分区，分区头统一为「11px 灰字小型化 + count 右对齐 + hover 才显示操作钮」。
- 备选 A：VS Code 式一树（收藏/最近变树内虚拟根节点）——信息密度最高但改动面最大，「最近」失去独立筛选体验。
- 备选 B：只压缩不动结构——三段抢滚动的根病灶不动。

## Q2 新建菜单的形状

**建议**：「＋ 新建」点击弹出下拉菜单（RibbonMenuButton/placeDrop 同款定位引擎），菜单为 **2×3 图标网格**：六个格式各带新家族徽标 + 格式名 + 扩展名小字；菜单底部一条「打开本地文件…」分隔项，替代现在的独立行。
- 连锁裁定：**菜单只放现有六格式**。mind/dxf 只做了图标资产、没有编辑器内核，不放入口（等工程图纸落地再补），避免点出去 404。

## Q3 新建的落点

**建议**：保持现有行为不变（handleNew* 直接创建并开标签页，落到当前上下文项目/默认位置）。本轮只动侧栏视觉，不动创建链路——减少回归面。

## Q4 收藏/最近两段的处置

**建议**：保留独立分区（Drive 式语义分区），但：① 收藏/最近的空态文案合并为一句（「还没有文件 — 从左上角新建或打开」）；② recents 的类型筛选 chips **降级为分区头右侧的一枚漏斗图标**（点击弹出同款筛选菜单），不再常驻占一行。
- 备选：彻底删掉 recents 筛选（最近列表本来就不长）。

## Q5 项目树视觉

**建议**：
- 行高 24px → **26px**（方圆徽标 16px 有呼吸感）；缩进每级 14px + **2px 缩进参考线**（hover 行时高亮所在层级 guide，VS Code 同款）。
- 文件行的 **checkbox 改 hover 才显示**（多选模式触发后常驻），星标同理——默认视觉减重。
- 项目头行（项目名+count+展开箭头）与文件行做**两级字重差**（项目名 12.5px 600 字重、文件 12px 400）。
- missing（文件丢失）态保留灰化+删除钮。

## Q6 云端 nav

**建议**：并入分区体系——变成「云端」分区头（与 收藏/最近 同款小型头，右侧外链箭头），不再孤占一行。

## Q7 分区头统一规格（三段共用）

**建议**：`11px · 灰字 · letter-spacing 0.4px · count 右对齐 · hover 显 + 钮`。项目段头右侧保留现有「新建项目 +」；收藏/最近头右侧 hover 出漏斗/清空钮。

## Q8 宽度降级

**建议**：极窄（180-210px）时「＋ 新建」「打开」两钮自动收为**纯图标钮**（title 提示兜底），折行不可能发生。现有 180-420 拖拽范围不变，默认 232 不变。

## Q9 web 版与移动端

**建议**：web 复用 shell 代码自动同步，零额外工作；移动端（MobileRibbon）无此侧栏，不在本次范围。两处确认点，无分歧可跳过。

## Q10 施工批次与验收

**建议**：
- **第一批（纯 CSS + 分区头组件化）**：分区头统一、行密度/缩进 guide/hover 减重、boot 画面不动。回归面最小。
- **第二批（新建区改造）**：七行 → 双钮+下拉菜单（复用 placeDrop 引擎），删除 side-links。
- **第三批（可选，默认不做）**：树虚拟根/拖拽排序——除非你点名。
- 验收：CDP 实景截图逐段对比 + 现有 Home 相关 vitest 全绿 + 180/232/420 三档宽度像素扫描。
