> 提取日期 2026-09-10。本文档记录 WPS 功能区图标资源的容器格式、破解过程、已解/未解部分，
> 以及本目录每个文件的来历。**所有资产仅供自绘图标时做风格参考，禁止复制进产品分发（金山美术资产）。**

## 三、qres 容器格式（已破解部分）

`.rcc` 不是 Qt 标准 rcc，是 WPS 自研容器，魔数 `qres`。布局三段式：

### 1. 头部（28 字节，大端）

| 偏移 | 内容 | 实测值（ico.rcc） | 含义 |
|---|---|---|---|
| 0x00 | magic | `qres` | |
| 0x04 | u32 version | 2 | |
| 0x08 | u32 f1 | 0x1CDB1F | **树区偏移**（[f1, EOF) = 树记录区） |
| 0x0C | u32 f2 | 0x14 = 20 | 恒为 20（= f1..f5 五个字段的总长，头大小自描述） |
| 0x10 | u32 f3 | 0x1CD245 | **名字区偏移**（[f3, f1) = 名字表） |
| 0x14 | u32 f4 | 0x5D02 | 未定（部分文件≈首块压缩长，未证实） |
| 0x18 | u32 f5 | 0x26E08 | 未定（ico.rcc=首块解压长；prometheus_kso=`\x89PNG` 即 0x89504E47，像首块内容类型提示） |
| 0x1C | 数据区 | — | 顺序 zlib 块，直到树区为止 |

### 2. 数据区（已破解）

- 一串**首尾相接的 zlib 流**（`78 01/5E/9C/DA`），每流自限定边界；解压到 `unused_data` 非空即到流尾。
- 实测每流 ≈ 一个资源文件；部分文件是**双层 zlib**（解一次还有 `78 xx` 头，再解一次才是 ICO/PNG 本体）。
- 流之间偶有少量空隙字节（跳过即可）。

### 3. 名字区 [f3, f1)（已破解，17 个表全部解析成功、区间精确耗尽）

记录 = `[u16 大端 长度][u32 大端 哈希][UTF-16**大端** 名字 × 长度个字符]`

```
例（ico.rcc）：00 11 | 0A D1 48 1F | 0070 006F 0073 ... → len=17, hash=0x0AD1481F, "poster_format.ico"
```

- 注意是 **UTF-16BE**（用 LE 解会得到「最椀昀」这类假名）。
- 名字含目录名（如 `icons`、`icons_svg`）与文件名（`cut_kd.svg`、`gsheet_filter_kd.svg`、`poster_format.ico`…）。
- 各表条目数：prometheus_kso 3355 / public 3414 / 2016white_highdpi 1993 / ongmani 2027 / mso_builtin 745 …（合计约 1.4 万条真名全部恢复）。

### 4. 树区 [f1, EOF)（结构已定位，join 规则未破）

ico.rcc 实测为 **22 字节定长记录**（从树区起点 +52 开始，逐条步进 22 验证通过）：

```
[u16 flag=0x0001][u16 A][u16 B][u32 0x000001A0 恒定][u32 DOS时间(如0x34292A23)][u32 C][u16 0x0001][u16 0x0000]
```

- C 值（1094、938、2160…）量级像文件尺寸，但与实际块解压长（159240…）对不上，含义未证实。
- A/B 曾假设为 (名字长度, 名字哈希16)：A 与任何真名长度都不符 → **解释错误**，真实语义未破。
- prometheus_kso 树区能按同步长扫出 4245 条（> 名字数 3355），说明可能混有第二类记录或目录项。

## 四、破解方法（怎么推出来的）

1. **数据区**：从 0x1C 起顺序找 zlib 魔数 → `decompressobj` 解压 → 用 `unused_data` 精确求出流尾 → 游标跳过去，直到树区。假阳性魔数靠"解压失败即跳过"过滤。
2. **名字区**：先把名字当 UTF-16LE 解出乱码（「最椀昀」= "gif" 的 LE 误读）→ 改 BE 后长度字段、哈希、区间耗尽三者同时吻合，格式即锁定。
3. **树区**：用行走出的 81 个块（偏移/压缩长/解压长）当"已知答案"，先在树区搜块偏移（无 → 数据顺序隐含偏移）；再用解压长序列顺序扫描（无匹配 → 该 u32 不是尺寸）；最后靠人眼对 24 字节/行 hex 网格找 `01 A0 34 29` 恒定串 → 22 字节步长水落石出。
4. **哈希 join 穷举（未中）**：对 (CRC16-CCITT/ARC、CRC32/ADLER 取高低 16 位、FNV1a-16、DJB2、sum×131、字节和) × (UTF-8/UTF-16BE) 全组合，用已知 (19 字符名 ↔ 0x56C2) 等样本验证，无一命中 → join 规则仍未破。

## 五、未破解清单（附线索）

1. **文件 ↔ 名字的最终对应**：树区 22B 记录里 [u16 A][u16 B] 的语义 + 名字表 u32 哈希的函数（观察：全部 ≤ 28 位，且大量以 0x??3F/5F/7F/9F/FF 结尾，疑似被 mask 的某标准哈希）。破开后即可按 `cut_kd.svg` 点名取文件，把各目录回填成真名。
2. **自研原始位图格式**（约 2400 个 `_bin` 文件，经典皮肤图标主体）：头 = `01 + 3 字节关键色`，后接零区与若干 u32（样本见 ico.rcc 262400 字节块 = 256 头 + 512×512 数据的猜想），尺寸字段位置未定位。自绘路线不依赖它。
3. prometheus_kso 树区多出的 ~890 条记录、f4/f5 字段语义——顺带解决。
